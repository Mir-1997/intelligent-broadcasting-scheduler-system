# REST API reference

Base URL (local): `http://localhost:8000`. Interactive docs are generated by FastAPI:

- Swagger UI: <http://localhost:8000/docs>
- ReDoc: <http://localhost:8000/redoc>
- OpenAPI JSON: <http://localhost:8000/openapi.json>

All bodies are JSON. Coordinates are WGS84 decimal degrees. Timestamps are UTC ISO-8601.
Examples below are real responses captured from the running service.

## Endpoint summary

| Method | Path | Purpose | Success |
|---|---|---|---|
| GET | `/admin` | Admin (map centre) | 200 |
| PUT | `/admin` | Replace admin name/location | 200 |
| POST | `/packages` | Add a package; pairs instantly if a rider is in range | 201 |
| GET | `/packages?status=waiting\|assigned` | List packages, oldest first | 200 |
| GET | `/packages/{id}` | One package | 200 / 404 |
| DELETE | `/packages/{id}` | Remove a **waiting** package | 200 / 404 / 409 |
| POST | `/riders` | Add a rider; pairs instantly if a package is in range | 201 |
| GET | `/riders?status=available\|assigned` | List riders, oldest first | 200 |
| GET | `/riders/{id}` | One rider | 200 / 404 |
| DELETE | `/riders/{id}` | Remove an **available** rider | 200 / 404 / 409 |
| GET | `/settings/radius` | Search-radius policy (start, increment, timer, cap) | 200 |
| PUT | `/settings/radius` | Replace the policy; applies to waiting packages immediately | 200 / 422 |
| GET | `/scheduler/state` | Waiting packages + available riders + admin + radius policy | 200 |
| POST | `/scheduler/reset` | Delete all packages, riders, assignments (admin kept) | 204 |
| GET | `/assignments?limit=50` | Assignment history, newest first (`1 ≤ limit ≤ 500`) | 200 |
| POST | `/simulate` | Spawn random packages/riders around the admin | 200 |
| GET | `/health` | Liveness | 200 |
| WS | `/ws/scheduler` | Live events: see [websocket-events.md](websocket-events.md) | |

Every write also publishes the matching WebSocket event(s).

## Admin

### `GET /admin`

```json
{ "name": "Admin HQ", "location": { "lat": 40.758, "lng": -73.9855 } }
```

The admin is seeded from `ADMIN_NAME` / `ADMIN_LAT` / `ADMIN_LNG` the first time the service
starts against an empty database. After that the Firestore document is the source of truth.

### `PUT /admin`

Body: same shape as the response. It replaces the admin and emits `admin.updated`, which
re-centres every open map.

```sh
curl -X PUT localhost:8000/admin -H 'content-type: application/json' \
  -d '{"name":"Lahore Hub","location":{"lat":31.5204,"lng":74.3587}}'
```

## Packages

### `POST /packages`

```json
{
  "pickup":  { "lat": 40.758,  "lng": -73.9855, "address": "1560 Broadway" },
  "dropoff": { "lat": 40.7484, "lng": -73.9857, "address": "350 5th Ave" }
}
```

`address` is optional (≤ 200 chars). Only the **pickup** is used for matching.

**201: paired straight away** (a rider was within range):

```json
{
  "package": {
    "id": "pkg_ff2b6b8f",
    "pickup":  { "lat": 40.758,  "lng": -73.9855, "address": "1560 Broadway" },
    "dropoff": { "lat": 40.7484, "lng": -73.9857, "address": "350 5th Ave" },
    "status": "assigned",
    "created_at": "2026-09-23T06:20:26.215329Z",
    "assigned_rider_id": "rdr_c14661b1",
    "assigned_at": "2026-09-23T06:20:26.221595Z"
  },
  "assignment": {
    "id": "asg_f09805ff",
    "package_id": "pkg_ff2b6b8f",
    "rider_id": "rdr_c14661b1",
    "rider_name": "Ali",
    "distance_miles": 0.768,
    "pickup":  { "lat": 40.758,  "lng": -73.9855, "address": "1560 Broadway" },
    "dropoff": { "lat": 40.7484, "lng": -73.9857, "address": "350 5th Ave" },
    "rider_location": { "lat": 40.7644, "lng": -73.9735 },
    "trigger": "package_added",
    "created_at": "2026-09-23T06:20:26.221595Z"
  }
}
```

**201: waiting** (no rider in range): `package.status == "waiting"`, `assignment == null`.

Events: `package.added`, then `assignment.created` if paired.

### `GET /packages`

Optional `status` filter (`waiting` or `assigned`). Returns `Package[]`, oldest first.
An invalid status gives 422.

### `GET /packages/{id}` → `Package`, or 404.

### `DELETE /packages/{id}`

Removes a waiting package and returns it. Emits `package.removed`.

| Case | Status | Body |
|---|---|---|
| Missing | 404 | `{"detail":"Package pkg_nope not found"}` |
| Already assigned | 409 | `{"detail":"Package pkg_… is already assigned"}` |

## Riders

### `POST /riders`

```json
{ "name": "Ali", "location": { "lat": 40.7644, "lng": -73.9735 } }
```

`name`: 1 to 60 characters. **201:**

```json
{
  "rider": {
    "id": "rdr_c14661b1",
    "name": "Ali",
    "location": { "lat": 40.7644, "lng": -73.9735 },
    "status": "available",
    "created_at": "2026-09-23T06:20:26.098334Z",
    "assigned_package_id": null,
    "assigned_at": null
  },
  "assignment": null
}
```

If a waiting package's pickup is within range, `rider.status == "assigned"` and `assignment`
is filled in with `"trigger": "rider_added"`.

Events: `rider.added`, then `assignment.created` if paired.

### `GET /riders`, `GET /riders/{id}`, `DELETE /riders/{id}`

These mirror the package endpoints (`status` is `available` or `assigned`). Deleting an
assigned rider gives **409** `{"detail":"Rider rdr_c14661b1 is already assigned"}`.

## Settings

### `GET /settings/radius` → `RadiusPolicy`

```json
{ "initial_radius_miles": 1.0, "increment_miles": 2.0, "interval_seconds": 30.0, "max_radius_miles": 15.0 }
```

A waiting package's search radius is `min(initial + increment × ⌊waited / interval⌋, max)`;
see [matching-algorithm.md](matching-algorithm.md#growing-search-radius).

### `PUT /settings/radius`

Body and response: `RadiusPolicy`. Constraints: `0 < initial_radius_miles ≤ 100`,
`0 ≤ increment_miles ≤ 100` (0 disables growth), `1 ≤ interval_seconds ≤ 86400`,
`initial_radius_miles ≤ max_radius_miles ≤ 200`; otherwise **422**. The policy is persisted,
emits `radius_policy.updated`, and immediately pairs any waiting package whose new radius
reaches an available rider (`assignment.created` with `trigger: "radius_expanded"`).

## Scheduler

### `GET /scheduler/state`

The same payload as the WebSocket `scheduler.snapshot` event. Use it for scripts or
debugging; the web app gets its state from the socket.

```json
{
  "admin": { "name": "Admin HQ", "location": { "lat": 40.758, "lng": -73.9855 } },
  "packages": [ /* waiting Package[] */ ],
  "riders":   [ /* available Rider[] */ ],
  "radius_policy": { "initial_radius_miles": 1.0, "increment_miles": 2.0,
                     "interval_seconds": 30.0, "max_radius_miles": 15.0 }
}
```

### `POST /scheduler/reset` → 204

Deletes every package, rider and assignment. The admin is kept. Emits `scheduler.reset`.

### `GET /assignments?limit=50`

`Assignment[]`, newest first. Backs the History panel.

### `POST /simulate`

```json
{ "packages": 5, "riders": 5, "radius_miles": 8 }
```

| Field | Range | Default | Meaning |
|---|---|---|---|
| `packages` | 0 to 50 | 5 | random packages to create |
| `riders` | 0 to 50 | 5 | random riders to create |
| `radius_miles` | > 0, ≤ 50 | 8 | spawn radius around the admin |

Items are created in random interleaved order, one at a time, through the normal matching
path (so every one produces the usual events). A drop-off is placed within 3 miles of each
pickup. Returns `{packages[], riders[], assignments[]}`, listing what was created.

## Errors

| Status | When | Body |
|---|---|---|
| 404 | Unknown id | `{"detail": "<message>"}` |
| 409 | Deleting an item that is already assigned | `{"detail": "<message>"}` |
| 422 | Validation failed | FastAPI's standard list, e.g. below |

```json
{"detail":[{"type":"less_than_equal","loc":["body","location","lat"],
            "msg":"Input should be less than or equal to 90","input":95,"ctx":{"le":90.0}}]}
```

The Flutter client turns this into the message `location.lat: Input should be less than or equal to 90`.

## Schemas

| Schema | Fields |
|---|---|
| `Location` | `lat` (−90…90), `lng` (−180…180) |
| `Place` | `Location` + `address` (string, default `""`) |
| `Admin` | `name`, `location: Location` |
| `Package` | `id`, `pickup: Place`, `dropoff: Place`, `status: waiting\|assigned`, `created_at`, `assigned_rider_id?`, `assigned_at?` |
| `Rider` | `id`, `name`, `location: Location`, `status: available\|assigned`, `created_at`, `assigned_package_id?`, `assigned_at?` |
| `Assignment` | `id`, `package_id`, `rider_id`, `rider_name`, `distance_miles`, `pickup`, `dropoff`, `rider_location`, `trigger: package_added\|rider_added`, `created_at` |

Ids are a prefix plus 8 random hex characters: `pkg_`, `rdr_`, `asg_`.

## CORS

Allowed origins come from `CORS_ORIGINS` (default `["*"]`, handy because `flutter run` picks
a random port). Restrict this for any public deployment.
